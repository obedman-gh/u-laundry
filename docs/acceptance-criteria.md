# Kriteria Website ULaundry Siap Dipakai

Versi baseline: 7 November 2026, commit `94ffc77`. Semua kotak **belum ditutup**; keberadaan sebagian implementasi bukan bukti acceptance. Audit hari 01 tidak menjalankan acceptance runtime. Gunakan fixture sintetis dan DB terisolasi, tanpa data pribadi/uang nyata.

## Gate penerimaan

- [ ] **AC01 — Setup/build:** clone bersih dengan toolchain terdokumentasi dapat build package; config contoh, migration up/status dan bootstrap owner tanpa password tetap dapat direproduksi. Fresh install → login → create order berhasil. Upgrade skema lama tidak kehilangan data. Bukti: command/result, migration version dan fixture. Hari 02–04/10/29; H01/H03/H08/H09.
- [ ] **AC02 — Konfigurasi/lifecycle:** production menolak secret kosong/placeholder/lemah, mode/origin/SSL tidak aman. Address, timeouts, pool, SSL, log level dan public URL configurable. Query/ping memiliki context deadline; SIGTERM menghentikan penerimaan request, menguras request dengan batas, menutup DB dan tidak mengklaim commit yang gagal. Bukti: config positive/negative, shutdown/failure check. Hari 03/25/26; H04/M02.
- [ ] **AC03 — Auth/session:** username/password salah memberi pesan generik; rate limit efektif. Exact signing algorithm, expiry dan issuer/audience/identity tervalidasi jika JWT dipakai. Cookie HttpOnly/Secure/SameSite dan CSRF sesuai strategi, atau keputusan penyimpanan alternatif beserta mitigasi tertulis. Logout/expiry/nonaktif user menutup akses, tanpa token/password pada log. Bukti: positive/negative auth tests, cookie/session inspection. Hari 09/19/24; H04–H06/C02.
- [ ] **AC04 — Authorization:** matriks owner/admin dan cashier ditegakkan server/use case untuk user, harga, order, payment/refund, shift, report dan audit. Cashier tak dapat mengubah role/harga atau membaca laporan/audit di luar izin lewat request langsung; anon ditolak dari data internal/receipt. Bukti: role matrix dan HTTP negative cases. Hari 10/15/17/24; H02/H06.
- [ ] **AC05 — Customer/privacy/tracking:** staff berwenang mencari/mengelola customer dan riwayat dengan data minimum; kontak/catatan opsional tervalidasi. Tracking memakai token acak kuat/unik, bukan ID yang ditebak; respons hanya kode/status/estimasi/pesan layanan, tanpa nama/kontak/uang/ledger internal. Token salah dan pencarian ID internal tidak membuka data. Bukti: DTO inspection, uniqueness/error/privacy/receipt authorization tests. Hari 11/21; H02.
- [ ] **AC06 — Layanan/harga:** owner mengelola layanan aktif, satuan kg/item, harga integer dan durasi. Order lama menyimpan snapshot; perubahan harga tidak mengubah tagihan lama. Layanan nonaktif ditolak untuk order baru. Bukti: unit calculation dan DB price-history evidence. Hari 05/12; H07.
- [ ] **AC07 — Create order:** staff memilih/buat customer, layanan, berat/jumlah, estimasi, diskon terotorisasi dan catatan; server menghitung subtotal/total integer rupiah dengan batas overflow. Total klien tidak dipercaya. Nilai negatif, kosong wajib, jumlah nol, tanggal tak valid dan diskon melampaui batas ditolak. Double-click/retry tidak menciptakan order ganda. Bukti: unit/HTTP/DB dan focused UI workflow. Hari 05–08/12/13/20; H01/H07.
- [ ] **AC08 — Workflow/concurrency:** status laundry terpisah dari pembayaran, semua transisi memiliki tabel aturan. Tidak bisa melompati/menurunkan status di luar aturan; milestone waktu konsisten. Dua staf dengan data lama menghasilkan hasil serial yang sah atau conflict yang jelas, tanpa lost update. Bukti: transition-table unit dan concurrent PostgreSQL tests, UI conflict handling. Hari 05/13/21; C01/H07.
- [ ] **AC09 — Payment/ledger:** payment memiliki identitas, order, method, amount, cashier, timestamp dan unique idempotency reference. Retry serial/concurrent dengan key sama membuat tepat satu payment/posting dan memberi hasil sama; key sama/payload berbeda ditolak. Kegagalan ledger membatalkan payment/order change; commit failure bukan sukses. Partial payment, overpayment, cancellation dan refund mengikuti aturan tertulis/disepakati; refund menambah jejak, tidak menghapus kas. Bukti: unit dan DB integration untuk semua kasus tersebut, unique/FK/check constraints dan rekonsiliasi. Hari 14; C01/H07/H08. Ini cash ledger, bukan klaim double-entry accounting.
- [ ] **AC10 — Shift/kas harian:** buka/tutup shift, saldo awal, cash in/out terotorisasi, payment tunai, saldo sistem/fisik, selisih dan catatan tercatat. Duplikasi shift aktif dicegah sesuai kebijakan; non-tunai terpisah. Cashier hanya shift sesuai izin, owner dapat merekonsiliasi. Bukti: DB/domain tests serta acceptance angka fixture dan cetak ringkasan. Hari 15/22; C01/M06.
- [ ] **AC11 — Dashboard/laporan:** order hari ini, antrean/terlambat, omzet terbayar, piutang, metode pembayaran dan shift sesuai fixture. Rentang tanggal/zona waktu bisnis eksplisit (Asia/Makassar pada baseline kebutuhan), pagination/filter bekerja; pembayaran/ledger sumber keuangan, bukan status laundry. Gangguan query menghasilkan error, bukan angka nol/sukses palsu. CSV aman dari formula injection. Bukti: DB angka/batas tanggal/failure, HTTP role dan UI export/print. Hari 16/22; H10/M01.
- [ ] **AC12 — Audit trail:** actor/action/target/time/request ID tercatat append-only untuk akun/role, harga, status, payment/refund dan shift close; metadata minimum tanpa secret. Cashier tak dapat mengubah jejak. Rollback transaksi tidak meninggalkan audit sukses palsu. Bukti: transactional audit dan authorization tests; retention terdokumentasi. Hari 17; M08.
- [ ] **AC13 — HTTP/DB correctness:** JSON/content type/body size/pagination divalidasi; error aman dan konsisten (validation 4xx, unauthorized/forbidden, not found, conflict, internal failure). Filter status benar, list kosong array, hasil stabil; DB error/rows.Err/scan/commit/rollback ditangani. Query parameter/context dipakai; constraint menjaga nilai/relasi penting. Bukti: handler negative tests, repository integration dan migration fresh/upgrade. Hari 04/06/08; H01/H07/H10/H11/M01–M04.
- [ ] **AC14 — Frontend aman:** data customer/order dirender sebagai teks/HTML yang dijamin escaping; payload HTML/script pada semua field tidak mengeksekusi script. Security headers dan CSP sesuai aset; allowed/disallowed origin dan OPTIONS teruji, tidak ada fallback wildcard production. Tidak ada data sensitif di cache publik/console/error. Bukti: negative HTTP/DOM checks. Hari 18–24; C02/H11/M03.
- [ ] **AC15 — UI dan receipt:** login/logout/session expired, POS, antrean/detail/filter/status, payment/refund, shift/report dan tracking selesai dari UI sesuai role. Bahasa Indonesia jelas tanpa slang; loading/empty/success/validation/error/offline tersedia. Keyboard/focus/label dan pesan error aksesibel; laptop dan Android 360–412 px tidak overflow horizontal pada alur utama. Struk internal berizin, escaping aman, identitas usaha benar, print preview dan printer 58/80mm diperiksa. Palet lama dipertahankan melalui CSS tokens. Bukti: daftar skenario/manual/browser, viewport dan perangkat/printer yang benar-benar dipakai; printer yang tidak tersedia dicatat Not Verified. Hari 18–22/29; H02/C02/M06/M07/L02.
- [ ] **AC16 — PWA/koneksi:** manifest/icon/installability, offline shell, online recovery dan update versi bekerja. Auth/API/customer/receipt/report tidak disimpan service worker secara sensitif. Operasi tulis offline menampilkan failure/retry terkendali, bukan queue diam-diam; retry tetap idempotent. Bukti: browser cache/update/offline checks. Hari 23; M06.
- [ ] **AC17 — Operasi/deployment/recovery:** liveness independen DB, readiness gagal terkontrol saat DB putus, log structured/request ID tanpa PII/secret, timeout dan panic response aman. Ubuntu non-root + service restart/reverse proxy/HTTPS/tunnel terkonfigurasi; port internal tak terekspos di luar rancangan. Backup terjadwal/permission/retention dan restore ke DB baru dibuktikan integritasnya. RPO/RTO dan rollback binary/aset/schema kompatibel disepakati. Bukti: isolated deployment smoke, config review dan restore drill; perubahan publik perlu otorisasi eksplisit. Hari 25–27; M02/M08.
- [ ] **AC18 — Dokumentasi/release evidence:** README clone sampai run, API, architecture, business/finance/privacy/security/testing, UI/PWA, deployment/backup/runbook dan changelog sesuai kode. CI tanpa secret production, unit/integration terpisah. Release checklist mencatat commit/artifact/schema, build, targeted unit/security/DB/concurrency/race relevan, fresh/upgrade dan focused E2E: login → customer/layanan → order → status → payment retry → receipt/tracking → shift/report → backup confirmation. Semua hasil nyata, bukan asumsi dari compile. Hari 28–30; H09/M05/L01.

## Keputusan bisnis yang masih harus ditetapkan

Sebelum acceptance terkait ditutup, dokumentasikan bersama pemilik: rounding berat/harga minimum/diskon, status/transisi lama ke baru, partial/overpayment/refund, payment methods, aturan shift/cash adjustments, token tracking/retention, session lifetime, identitas usaha/nomor kontak struk, domain/infrastruktur, serta RPO/RTO. Jangan mengubah data nyata atau mengintegrasikan pembayaran eksternal berdasarkan asumsi dokumen ini. Pilihan sederhana dapat dibuat bertahap sepanjang tidak mengubah perilaku bisnis material tanpa kesepakatan.

## Aturan rilis

Hari 29–30 memberi status **Verified**, **Accepted Risk** (alasan/pemilik/tindak lanjut), atau **Not Verified** untuk setiap AC. Critical/High audit harus ditutup dengan bukti, bukan sekadar pindah folder. Gap Medium/Low hanya boleh diterima eksplisit bila tidak melanggar integritas uang, privacy atau alur wajib. Not Verified pada uang/security/migration/restore atau workflow utama tetap blocker. Jadwal 30 hari merupakan rencana, bukan tenggat yang membenarkan melewati gate.

Jika tidak ada environment/otorisasi publik, hasil maksimal adalah release artifact dan prosedur deployment; jangan menandai deployment atau production-ready sebagai Verified. Gate hari 01 hanya dokumen dan build baseline, bukan seluruh daftar di atas.
